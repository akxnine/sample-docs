HOW AN AGENT HARNESS WORKS

An LLM in a vacuum only predicts tokens. The Agent Harness is the deterministic operating system around the model—managing state (`ctx`), intercepting tool calls, enforcing guardrails, and verifying outputs.

Every `tool_call` emitted by the model is just a JSON proposal. The harness validates the JSON schema, checks path/command allowlists, blocks repeating zombie calls, and pauses for Human-in-the-Loop approval on high-risk operations.

policy.verify(call) → ALLOW | DENY | HITL
DEFENSE-IN-DEPTH SPECIFICATION

THE 3-GATE HARNESS GUARDRAILS ARCHITECTURE

Never rely on system prompt politeness ("Please don't drop tables") as security!
GATE 01 // INGRESS & CONTEXT Pre-Model

Sanitizes user prompts & untrusted tool observations before context injection:

  • PII & Secret Scrubbing: Regex + NER replaces API keys, SSNs, and tokens with vault placeholders.
  • Indirect Injection Shield: Delimits untrusted web/email data in structural XML tags & scans for override payloads.
  • Budget & Rate Quotas: Enforces max token and dollar ceiling per session.
Action on Trigger: Redact inline or abort turn
GATE 02 // EXECUTION SANDBOX Critical Gate

Intercepts every proposed `tool_call` before real-world execution:

  • Strict JSON Schema Validation: Rejects hallucinated parameters and returns compiler-style error hints.
  • MicroVM / Container Isolation: Runs code in gVisor/Docker with read-only mounts & network egress allowlists.
  • Scoped Token Injection: Proxy injects short-lived credentials; LLM never sees raw secrets.
Action on Trigger: Pause for HITL or block (`#9e2a2b`)
GATE 03 // VERIFICATION HOOK Post-Model

Proves the agent's output is grounded and functional before completion:

  • Deterministic Test/Linter Hooks: Automatically runs `tsc`, `pytest`, or SQL `EXPLAIN` before accepting completion.
  • Citation & Grounding Audit: Verifies cited file lines or record IDs exist in session tool traces.
  • Structured Output Repair: Enforces final response schema or forces a self-correction turn.
Result: Emits VERIFIED OUTPUT badge

SHEET 02 // HARNESS ENGINEERING PRINCIPLES
CONTEXT HYGIENE • SELF-HEALING SIGNALS • TOOL ERGONOMICS
Production Architecture Patterns:

BEST DESIGN PRACTICES

Benchmark-winning agents often share the exact same foundation model as failing ones. The difference lies in three harness design pillars.

PILLAR 01 // TOOL ERGONOMICS

Real Generalization

Resist tool proliferation. Giving an agent 75 overlapping micro-tools bloats the prompt prefix and degrades selection accuracy.

✓ The Orthogonal Core (≤ 15 Tools):
• `read_file` / `edit_file`
• `grep_search` / `glob_files`
• `bash_sandbox` (Unix composability)
• `spawn_subagent` / `load_skill`

Design Poka-Yoke tool schemas: require absolute file paths, enforce enum constraints, and use line-anchored search-and-replace instead of whole-file overwrites.

Rule: Primitive Tools + Composable Skills
PILLAR 02 // CLOSED-LOOP FEEDBACK

Precise Error Signals

Turn exceptions into steering signals. When a tool call fails, never swallow the error or dump a 300-line raw stack trace.

✗ Bad: "Error 500: SQLiteException"
✓ Harness Diagnostic Signal:
"Column 'usr_id' not found in 'orders'. Available columns: [id, account_id, total_cents]. Hint: retry with account_id."

Feed concise compiler, linter, or schema diagnostics back via ctx.append(err) so the model self-heals on the very next turn.

Rule: Actionable Diagnostics Enable Self-Repair
PILLAR 03 // L1 CACHE HYGIENE

Protected Competence

Guard the context window against "Context Rot." Reasoning quality drops sharply when noisy logs push critical instructions into the middle of a bloated window.

  • Hard Output Truncation: Cap inline tool outputs at 200 lines / 8KB; offload full payloads to scratchpad files on disk.
  • Pinned Task Ledger: Keep `TODO.md` pinned at the end of context to prevent goal drift across 30+ turns.
  • Auto-Compaction at 75%: Summarize older turns into structured state checkpoints before hitting limits.
Rule: Treat Context as Scarce L1 CPU Cache

SHEET 03 // ARCHITECTURAL DECISION MATRIX
COMPLEXITY TRADEOFFS • RAW LLM VS. DAG WORKFLOW VS. AGENT HARNESS
Architectural Justification:

WHEN & WHY TO USE A HARNESS

Use the simplest abstraction that solves the problem. Deploy a full Agent Harness only when the execution trajectory cannot be hardcoded in advance.

WITHOUT AN AGENT HARNESS Open-Loop / Fragile

Raw LLM Inference in a Vacuum

  • ✗Blind One-Shot Guessing: Generates 500 lines of code or advice without checking if files exist or compile.
  • ✗Zero Self-Recovery: A single syntax error or missing import fails the entire user request.
  • ✗Ephemeral Memory: No durable state across turns, crashes, or human approval pauses.
  • ✗Unbounded Risk: No policy layer between model hallucinations and production APIs.
WITH AN AGENT HARNESS Closed-Loop / Verified

Why Engineers Wrap Models in a Harness

  • ✓Empirical Grounding: Inspects real schemas, files, and logs via tools before proposing changes.
  • ✓Iterative Self-Healing: Observes compiler/test failures and iterates 3–20 times until checks pass.
  • ✓Durable Checkpoints: Serializes state after every step for crash recovery and async human sign-off.
  • ✓Deterministic Governance: Enforces token budgets, sandboxes, and RBAC around non-deterministic reasoning.

POSTER 04 // ARCHITECTURAL PRIMITIVES & CONTEXT ISOLATION
DOT-GRID SPEC v2.6
TAXONOMY OF CAPABILITIES

TOOLS, AGENTS & SUBAGENTS

Confusing a Tool with an Agent or Subagent leads to monolithic, fragile architectures. Each primitive operates at a distinct layer of state and autonomy.

01 // ATOMIC TOOL Stateless Function

Deterministic Hands & Sensors

A Tool has zero intelligence or agency. It is a typed function contract (`JSON Args → Deterministic Code → String/JSON Result`) executed by the harness on behalf of an agent.

// Examples of Tools:
• read_file(path, offset, limit)
• bash_exec(cmd, timeout_ms)
• mcp_postgres_query(sql)
LLM Loop: None (0 turns) 100% Code
02 // LEAD AGENT Main Thread

Stateful Goal Orchestrator

An Agent is a model running inside a `while` loop with persistent conversation state (`ctx`). The Lead Agent owns the user relationship, global plan, and final synthesis.

// Core Responsibilities:
• Decompose ambiguous user goals
• Maintain pinned `TODO` task ledger
• Delegate noisy work to Subagents
Context: Global Session Frontier Model
03 // SUBAGENT Isolated Worker

Scoped Context Firewall

A Subagent is a child agent loop spawned via `task()` with a fresh, isolated context window and restricted tools. When finished, its 50k-token scratchpad is garbage-collected.

// Why Spawn a Subagent?
• Shield Lead Agent from 50k grep logs
• Run 3 research tracks in parallel
• Enforce least-privilege (read-only)
Returns: Distilled Summary Ephemeral

                            ARCHITECTURAL DECISION GUIDE
                        
                        
When to Use a Skill vs. Tool vs. System Prompt?

                    


                    

                        

                            
📘 USE A SKILL (`SKILL.md`) WHEN:

                            

                                You need domain-specific standard operating procedures (SOPs), multi-step checklists, code conventions, or bundled helper scripts that are only relevant to specific tasks (e.g., * Zero-Downtime Postgres Migration*, *Design System Audit*, *CVE Triage*).
                            

                        


                        

                            
🔧 USE AN ATOMIC TOOL WHEN:

                            

                                The model needs a deterministic capability to read/write external state, execute binary code, or authenticate with an API (`bash`, `sql_query`, `github_pr`).
                            

                        


                        

                            
📌 USE SYSTEM PROMPT (`AGENTS.md`) WHEN:

                            

                                A rule applies to 100% of turns in every session (e.g., repo build commands, global safety boundaries, core tone). Keep under 1,500 tokens!
                            

                        

                    

                

            


            
            

                

                    

                        BEYOND TOY DEMOS // PRODUCTION CHECKLIST
                        

                            6 CRITICAL HARNESS DETAILS OFTEN MISSED ("THE HIDDEN 20%")
                        

                    

                    
                        These 6 subsystems separate a weekend prototype from an enterprise harness!
                    
                


                
                

                    
                    

                        

                            01 // LOOP GOVERNANCE
                            Anti-Thrash
                        

                        
Zombie Loop & Semantic Cycle Detection

                        

                            Agents frequently get stuck calling the exact same failing command 10 times. The harness hashes `(tool_name + normalized_args)` and injects a mandatory strategy-shift interrupt after 3 identical failures.
                        

                    


                    
                    

                        

                            02 // STATE DURABILITY
                            Replay / Fork
                        

                        
Time-Travel Checkpointing

                        

                            If an agent takes a wrong turn at Step 15, you shouldn't restart from Step 1. Harnesses snapshot both the conversation JSON and the sandbox git tree at every turn for instant rewind.
                        

                    


                    
                    

                        

                            03 // COST & LATENCY
                            -80% Spend
                        

                        
Heterogeneous Model Routing

                        

                            Don't burn frontier reasoning tokens on grep parsing. Route Lead Agent planning to a frontier model, Subagent file search to a fast Flash/Haiku tier, and Ingress Guardrails to a tiny classifier.
                        

                    


                    
                    

                        

                            04 // OBSERVABILITY LAYER
                            OpenTelemetry
                        

                        
Trajectory Evals (`pass@k` vs `pass^k`)

                        

                            Grading only the final answer hides brittle behavior. Production harnesses evaluate the full execution trajectory: redundant tool calls, guardrail near-misses, token burn, and consistency across `k` runs.
                        

                    


                    
                    

                        

                            05 // MEMORY LIFECYCLE
                            Anti-Context-Rot
                        

                        
Structured Compaction Handoffs

                        

                            When context reaches 75% capacity, the harness runs a structured summarization turn that prunes old raw tool outputs while preserving modified file paths, verified facts, and open blockers.
                        

                    


                    
                    

                        

                            06 // LIVE HUMAN STEERING
                            Async UX
                        

                        
Graceful Interrupts & Mid-Flight Steering

                        

                            Users watching a live agent often spot a wrong assumption mid-loop. The harness supports clean SIGINT cancellation of running child subagents and injects user course-corrections without losing state.
