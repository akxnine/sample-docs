          Section 02 • Zero-Trust Defense-in-Depth
          
6-Layer Guardrails & Governance Architecture

        

        

          Agent Fabric never bypasses underlying data security. Every query executes inside a concentric 6-ring security boundary.
        

      


      

        
        

          

            
Defense-in-Depth Topology

            
Concentric Security Rings

            
From outer prompt intake down to inner OneLake parquet blocks.

          


          
          

            
          


          

            
            

              Zero Privilege Escalation Guarantee: Even if a prompt instructs the agent to summarize Executive Payroll, the underlying SQL/DAX/KQL engine rejects or masks rows based on the calling user's Entra ID token.
            

          

        


        
        

          

            

              01 • IDENTITY PASSTHROUGH
              OAuth2 OBO
            

            
Strict User Context & RLS/CLS/OLS

            

              Fabric Data Agents execute all queries using the calling user's Microsoft Entra ID identity (On-Behalf-Of flow). Row-Level Security (RLS), Column-Level Security (CLS), and Object-Level Security (OLS) configured in Lakehouse, Warehouse, or Power BI are enforced natively.
            

          


          

            

              02 • DATA MUTATION LOCK
              Immutable
            

            
100% Read-Only Query Gate

            

              Connections to Fabric data sources are hard-locked to read-only operations. Any generated SQL, DAX, or KQL containing DDL/DML mutations (DROP, DELETE, UPDATE, INSERT, ALTER, .drop) is blocked at the syntax validator before reaching compute.
            

          


          

            

              03 • PURVIEW GOVERNANCE
              DLP + Labels
            

            
Microsoft Purview Sensitivity & DLP

            

              Data Agents inherit Microsoft Purview sensitivity labels (e.g., Highly Confidential) and Data Loss Prevention (DLP) policies. Audit logs track every user prompt, generated query, accessed semantic object, and synthesized response.
            

          


          

            

              04 • CURATED SCOPE BOUNDARY
              Schema Whitelist
            

            
Explicit Table & Column Whitelisting

            

              Creators explicitly check which tables, views, or semantic measures are visible in the Agent Explorer. Unchecked tables in the same Lakehouse are invisible to the agent's schema discovery and forbidden during query validation.
            

          


          

            

              05 • CONTENT SAFETY & RAI
              Prompt Shields
            

            
Jailbreak & Groundedness Verification

            

              Built-in Azure AI Content Safety filters block indirect prompt injections embedded inside database text columns and verify that synthesized numerical answers are strictly grounded in the returned query result set.
            

          


          

            

              06 • HARNESS MIDDLEWARE
              HITL + Sandbox
            

            
Tool Approval & Script Sandboxing

            

              In the Microsoft Agent Framework, ToolApprovalMiddleware auto-approves read-only tools (ReadOnlyToolsAutoApprovalRule) while requiring human-in-the-loop (HITL) approval and isolated container sandboxes for script execution (run_skill_script).

          Section 04 • Deterministic Execution Primitives
          
What Are Tools in Microsoft Agent Fabric?

        

        

          Tools are atomic, schema-typed capabilities invoked by an Agent to query data, run calculations, or interact with external APIs deterministically.
        

      


      
      

        
        

          

            

              Category A • Built-In Fabric Data Tools
              
Native Analytical Query Engines

            

            Managed by Fabric
          


          

            

              

                NL2SQL Tool
                T-SQL / Spark SQL
              

              

                Translates natural language into optimized T-SQL queries against Fabric Lakehouses (SQL Analytics Endpoint) and Fabric Data Warehouses.
              

            


            

              

                NL2DAX Tool
                Power BI Semantic
              

              

                Generates validated DAX queries against Power BI Semantic Models, preserving verified business measures, hierarchies, and calculation groups.
              

            


            

              

                NL2KQL Tool
                Eventhouse / RTI
              

              

                Generates high-speed Kusto Query Language (KQL) queries for Real-Time Intelligence Eventhouses to analyze streaming logs, IoT, and time-series data in place.
              

            


            

              

                Ontology / Graph Tool
                GQL / Entity Graph
              

              

                Traverses semantic relationships, business entities, and multi-hop graph topologies across Fabric Ontologies and Microsoft Graph.
              

            

          

        


        
        

          

            

              Category B • Agent Framework & Foundry Tools
              
Programmable & External Action Tools

            

            C# / Python / MCP
          


          

            

              

                Function Tools (AIFunction)
                In-Process
              

              

                Strongly-typed C# (AIFunctionFactory.Create) or Python functions decorated with JSON Schema descriptions for custom business logic or API calls.
              

            


            

              

                MCP Tools
                Model Context Protocol
              

              

                Standardized client-server tool protocol allowing agents to discover and invoke remote enterprise tools, databases, and SaaS connectors dynamically.
              

            


            

              

                Sandboxed Script Runner
                Code Interpreter
              

              

                Executes Python (.py), PowerShell (.ps1), or C# scripts inside isolated containers for statistical modeling, forecasting, or file validation.
              

            


            

              

                OpenAPI & Logic Apps
                1,400+ Connectors
              

              

                Triggers external workflows in ServiceNow, SAP, Salesforce, or Jira when an analytical insight from Fabric requires downstream action.

What Are Agents vs. Subagents?

        

        

          Instead of cramming 60 tables and 15 tools into a single bloated agent, Microsoft Agent Fabric uses modular Orchestrator Agents and specialized Subagents.
        

      


      
      

        

          

            

              Tier 1 • Root Orchestrator
              Foundry / Copilot Studio
            

            
Primary / Orchestrator Agent

            

              The user-facing intelligence that owns the conversation thread, global memory, intent decomposition, multi-step planning, and final response synthesis.
            

            
    
              
  • • Decomposes complex cross-domain prompts
    • 
              
  • • Routes sub-tasks to specialist Subagents
    • 
              
  • • Loads cross-cutting Skills (SKILL.md)
    • 
              
  • • Synthesizes outputs into executive narratives
    • 
            

          


          

            

              Tier 2 • Domain Specialists
              Fabric Data Agents
            

            
Subagents (Domain Specialists)

            

              Focused, autonomous agents encapsulated with their own system prompt, domain glossary, golden few-shot examples, and a curated set of up to 5 Fabric data sources.
            

            
    
              
  • • Isolated context window (prevents schema pollution)
    • 
              
  • • Independently versioned, evaluated & governed
    • 
              
  • • Exposed via Connected Agent / Agent-as-a-Tool
    • 
              
  • • Example: Finance PBI Agent, IoT Eventhouse Agent

          Section 07 • Progressive Disclosure Domain Packages
          
How & When to Use Agent Skills (SKILL.md)

        

        

          Agent Skills are portable directories containing a SKILL.md manifest, reference assets, and scripts that load progressively on demand instead of bloating the system prompt.
        

      


      
      

        

          

            PHASE 1 • ADVERTISE
            ~100 Tokens
          

          
Frontmatter Discovery

          

            At startup, AgentSkillsProvider scans configured skill directories and injects only the YAML name and description into the system prompt.
          

          

            Cost: Minimal context footprint even with 30+ installed skills.
          

        


        

          

            PHASE 2 • LOAD
            < 5,000 Tokens
          

          
load_skill(skill_name)

          

            When a user's prompt matches the skill's description, the LLM calls the built-in load_skill tool to pull the full Markdown SOP body of SKILL.md.
          

          

            Recommendation: Keep SKILL.md under 500 lines.
          

        


        

          

            PHASE 3 • RESOURCES
            On-Demand I/O
          

          
read_skill_resource

          

            If the SOP requires specific tax tables, JSON schemas, or policy templates, the agent invokes read_skill_resource to fetch files from references/ or assets/.
          

          

            Supports: .md, .json, .yaml, .csv, .xml, .txt (2–3 levels deep).
          

        


        

          

            PHASE 4 • SCRIPTS
            HITL Guarded
          

          
run_skill_script

          

            For deterministic math or validation, the agent invokes run_skill_script on scripts/*.py or *.ps1, gated by ToolApprovalMiddleware.
          

          

            Security: Path traversal & symlink escapes strictly blocked.

          Section 08 • Production Engineering Playbook
          
8 Best Design Practices for Microsoft Agent Fabric

        

        

          Battle-tested architectural patterns to maximize NL2SQL/DAX/KQL accuracy, minimize token latency, and prevent hallucinations.
        

      


      

        
        

          

            

              RULE 01 • SCHEMA HYGIENE
              ≤ 5 Sources
            

            
Curate & Prune Schema Scope

            

              Only check the specific tables, views, and columns required for the domain. Exposing 200 staging tables degrades NL2SQL routing accuracy and inflates prompt tokens.
            

          

          

            
✓ DO: Expose 8–15 curated Gold Star-Schema tables.

            
✕ AVOID: Selecting raw Bronze ingestion tables.

          

        


        
        

          

            

              RULE 02 • GLOSSARY GROUNDING
              Agent Instructions
            

            
Encode Acronym & Fiscal Rules

            

              Use Fabric Data Agent instructions to define company-specific terminology (e.g., "FY26 starts July 1", "Active Customer = Status_Code IN (1,4)"), and preferred table routing.
            

          

          

            
✓ DO: Map business terms to exact column names.

            
✕ AVOID: Vague prose without column references.

          

        


        
        

          

            

              RULE 03 • FEW-SHOT SEEDING
              Example Queries
            

            
Seed Golden Few-Shot Pairs

            

              Provide 10–25 verified Question-to-SQL/KQL/DAX examples in the Data Agent configuration covering complex multi-table joins, window functions, and time-intelligence.
            

          

          

            
✓ DO: Seed edge-case joins & YoY calculations.

            
✕ AVOID: Relying zero-shot on cryptic legacy schemas.

          

        


        
        

          

            

              RULE 04 • SEMANTIC LAYER FIRST
              NL2DAX Priority
            

            
Use Semantic Models for KPIs

            

              Never force an LLM to reinvent complex accounting formulas in raw SQL when a validated Power BI Semantic Model measure already exists. Route KPI queries to NL2DAX.
            

          

          

            
✓ DO: Query verified DAX measures for Margin/ARR.

            
✕ AVOID: Ad-hoc SQL math on unaggregated ledgers.

          

        


        
        

          

            

              RULE 05 • CONTEXT BUDGETING
              SKILL.md
            

            
Offload Runbooks to Skills

            

              Move specialized audit workflows, compliance checklists, and statistical scripts out of the global system prompt and into modular SKILL.md packages.
            

          

          

            
✓ DO: Keep SKILL.md <500 lines + reference files.

            
✕ AVOID: 15,000-token monolithic system prompts.

          

        


        
        

          

            

              RULE 06 • DOMAIN FEDERATION
              Subagent Topology
            

            
Split by Domain into Subagents

            

              Build dedicated Fabric Data Agents per business domain (Finance, Supply Chain, HR, Telemetry) and compose them via an Azure AI Foundry or Copilot Studio Orchestrator.
            

          

          

            
✓ DO: 3 focused Data Agents federated by 1 Root.

            
✕ AVOID: Mixing unrelated schemas in 1 agent.

          

        


        
        

          

            

              RULE 07 • RBAC VERIFICATION
              Multi-Persona QA
            

            
Test with Restricted Personas

            

              Developers often test agents using Workspace Admin accounts. Always test with low-privilege service test accounts to verify RLS, CLS, and Power BI Read permissions.
            

          

          

            
✓ DO: Validate graceful handling of RLS-empty rows.

            
✕ AVOID: Testing only with Admin / Owner tokens.

          

        


        
        

          

            

              RULE 08 • AUTOMATED EVALS
              Fabric SDK CI/CD
            

            
Run Golden Evaluation Suites

            

              Use the Fabric Data Agent Python SDK and Foundry Evaluators to run automated batch evaluations (SQL equivalence, groundedness, latency) before promoting across stages.
            

          

          

            
✓ DO: Gate deployment pipelines on ≥92% accuracy.

            
✕ AVOID: Manual "vibe-check" prompt edits in Prod.

          

        

      

    


    
    

      

        

          Section 09 • Architectural Nuances & Gotchas
          
6 Critical Details Engineers Often Miss

        

        

          Key licensing, permission, real-time querying, and lifecycle nuances that separate smooth enterprise rollouts from troubleshooting bottlenecks.
        

      


      

        

          

            GEM #1 • POWER BI PERMISSIONS
          

          
Only "Read" Permission Needed on Semantic Models

          

            Historically, querying a Power BI Semantic Model required granting users Build permission (which also let them build their own reports). With Fabric Data Agents, end-users only need Read permission on the Semantic Model to ask natural language questions!
          

        


        

          

            GEM #2 • ZERO-MOVEMENT REAL-TIME KQL
          

          
In-Place Eventhouse Streaming Queries

          

            When you attach an Eventhouse KQL database to a Fabric Data Agent, queries execute in-place against live streaming ingestion tables with sub-second indexing—no batch copy or mirroring lag required.
          

        


        

          

            GEM #3 • DIAGNOSTIC QUERY TRANSPARENCY
          

          
Full Intermediate Step & Query Inspection

          

            Every response generated by a Fabric Data Agent includes an expandable execution trace showing the exact generated SQL, DAX, or KQL code and intermediate tool outputs so analysts can verify auditability.
          

        


        

          

            GEM #4 • PROGRAMMATIC SDK & CI/CD
          

          
Fabric Data Agent Python SDK & Git ALM

          

            You don't have to configure Data Agents solely by clicking in the browser UI. You can programmatically create, configure, seed few-shot examples, and run batch evaluations via the fabric-data-agent-sdk inside Fabric Notebooks and Git-integrated workspaces.
          

        


        

          

            GEM #5 • MULTI-CHANNEL PUBLISHING
          

          
Native Consumption in Foundry & Copilot Studio

          

            A published Fabric Data Agent generates a stable endpoint URL and metadata contract. In Azure AI Foundry or Microsoft Copilot Studio, you attach it in 2 clicks as a connected knowledge/agent resource with zero custom glue code.
          

        


        

          

            GEM #6 • CAPACITY & TENANT SWITCHES
          

          
Paid F-SKU Capacity & Tenant Admin Prerequisites

          

            Creating and querying Fabric Data Agents requires a paid Fabric Capacity (F2 or higher) or Trial capacity, plus Tenant Admin enablement for Copilot/Azure OpenAI switches and cross-geo processing if your capacity region differs from the AOAI host region.
