What Is Microsoft Agent Fabric?

Unifying Microsoft Fabric Data Agents (OneLake) and the Microsoft Agent Framework into a governed enterprise runtime. Save this for later.

1. How it works: think, route, query, ground

A user prompt never queries raw storage unchecked. The orchestrator binds the caller's Entra ID token, routes to a specialized tool or Data Agent, validates the AST, and grounds the answer in OneLake rows.

4. Guardrails: Entra OBO, RLS & AST Gate

Every tool invocation passes through an identity and syntax gate: read-only queries execute with the user's RLS/CLS token, sensitive actions pause for human approval, and mutations are hard-blocked.

5. When to use & Why to use

Use Agent Fabric when business users need governed, multi-source insights over OneLake without data movement. Avoid it for high-frequency OLTP row mutations.

6. Agents vs. Subagents: split the work

The Lead Orchestrator Agent holds user conversation state and delegates domain queries to specialized Fabric Data Subagents—each with its own curated schema and isolated context.

Understanding Agent Skills (SKILL.md)

Portable domain packages: how Progressive Disclosure scales agent expertise to 100+ enterprise workflows without context bloat.

1. Monolithic Prompt vs. Progressive Skills

Stuffing every financial rulebook into the system prompt burns ~42K tokens on every turn. `FileAgentSkillsProvider` advertises only YAML frontmatter (~100 tokens/skill) and loads full SOPs on demand.

2. The 3-Phase Progressive Disclosure Funnel

Skills load in three strict stages so your agent only pays the token cost for the exact workflow and reference file required by the current prompt.

Phase 1 · Advertise (Startup)
Injects YAML name + description only
~100 tokens
Phase 2 · load_skill(name)
Pulls full Markdown SOP body (<500 lines)
~1,500 tokens
Phase 3 · read_skill_resource / run_script
Fetches references/*.md or runs sandbox script
0 prompt bloat

5. Skills vs. Tools vs. Subagents

How to choose the right architectural primitive in Microsoft Agent Fabric when designing a new capability.

📘 Use a SKILL (SKILL.md) when:
You are packaging HOW to perform a repeatable domain methodology (audit checklists, KPI formulas, reference tables, helper scripts).
🔧 Use a TOOL (NL2SQL / NL2DAX / MCP) when:
You need deterministic WHAT execution against live databases, semantic models, or external REST APIs.
🧭 Use a SUBAGENT (Fabric Data Agent) when:
You need WHO isolation: a separate curated schema (<=5 data sources), distinct RBAC scope, or isolated context window.

6. Best Practices for Authoring Skills

Follow these four rules so `AgentSkillsProvider` discovers and executes your skills reliably without path vulnerabilities.

01. Trigger-Rich YAML

Write explicit trigger keywords in description; Phase 1 routing relies 100% on frontmatter.

02. Keep Body < 500 Lines

Keep SKILL.md concise; move large lookup tables into references/*.md.

03. Relative Paths Only

AgentSkillsProvider blocks .. traversal and symlinks outside the skill root.

04. Gate Script Runner

Wrap run_skill_script in ToolApprovalMiddleware + container sandboxes.
